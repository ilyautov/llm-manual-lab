## 13 Контекст и KV cache

<!-- e:143 -->
Контекст — информация, доступная модели в текущем вызове. Туда могут входить системные инструкции, запрос, выбранная история, документы, примеры, результаты инструментов и уже сгенерированная часть ответа.

<!-- e:144 -->
Контекстное окно — поддерживаемый лимит последовательности. Правила учёта входа, ответа и внутренних токенов зависят от модели и сервиса. Техническая возможность принять длинный текст не гарантирует надёжное использование каждой детали. Lost in the Middle обнаружил чувствительность некоторых моделей к позиции нужной информации в длинном контексте [16]. Конкретный результат нельзя автоматически переносить на каждую новую модель, но проверка остаётся полезной.

<!-- e:145 override -->
In-context learning означает адаптацию поведения по данным внутри запроса без обновления весов. Если показать три размеченные заявки, модель может по аналогии обработать четвёртую. После удаления этих примеров из входа нельзя рассчитывать на их сохранение в параметрах.

<!-- e:146 override -->
KV cache хранит ключи K и значения V предыдущих позиций, чтобы повторно использовать их при генерации. В работе о PagedAttention предложено распределять блоки этой памяти по мере необходимости для эффективного обслуживания запросов [17].

<!-- e:147 override -->
Prefix caching повторно использует вычисления общей начальной части запросов, если runtime поддерживает эту функцию. Префикс должен совпадать точно; кеш действует по правилам хранения конкретного сервиса и не исправляет ошибки в исходном контексте.

<!-- e:148 override -->
FlashAttention уменьшает перемещения данных между уровнями памяти при точном attention [18]. KV cache решает другую задачу: сохраняет K и V уже обработанных позиций для следующих шагов генерации.

<!-- e:149 -->
Для лаборатории. Большое окно, быстрый кеш и долговременная память решают разные задачи. В техническом предложении они должны быть названы отдельно.
