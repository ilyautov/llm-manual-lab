# Пять разных сигналов для одного сбоя

Учебный сбой: система сообщила «42 оплаченных заказа», но в трассе нет вызова `paid_orders`. Даже если в тестовой базе действительно 42 записи, такой ответ нельзя считать проверенным. Цель обучения — научить систему выбирать проверяемое действие и опираться на его результат. Текущее число остаётся в базе.

| Метод | Конкретный сигнал | Какие параметры меняются | Независимая проверка |
| --- | --- | --- | --- |
| Continued pretraining | Текст описания `paid_orders(date,status) → count`, цель — предсказание следующего токена | Параметры языковой модели | Понимает ли новые описания API; не ухудшились ли общие задачи |
| SFT | Запрос + эталонный вызов с точными аргументами + ответ по возвращённому `count` | Параметры модели или адаптера | Новые даты, пустые результаты, отказ в доступе |
| Предпочтения | Пара: проверенный ответ A и уверенное неподтверждённое «42» B; предпочтение A | Параметры через выбранный алгоритм post-training | Отдельно измерять правдивость и выполнение задачи, не только предпочтение оценщика |
| RLVR | Тестовый runtime выдаёт 1 только за разрешённый вызов, правильный фильтр и ответ по результату, иначе 0 | Параметры политики | Скрытые тесты против обхода проверяющего и запоминания дат |
| Дистилляция | Проверенные трассы учителя становятся целями меньшей модели | Параметры ученика | Перенос на новые даты и стоимость успешного ответа |

LoRA относится к способу обновления выбранных матриц, а не к самостоятельной цели обучения. Примеры внутри запроса и RAG меняют вход на этапе инференса; веса при обычном вызове остаются прежними.

## Минимальный закрытый тест

Составьте случаи, которых нет в обучающих записях: день с нулём заказов, пользователь без `orders:read`, недоступная база и дата с иным количеством. Для каждого заранее задайте ожидаемый вызов, проверку права и допустимую фразу ответа. Сравнивайте трассы и цену успешного случая, а не только гладкость формулировок.
