# Лаборатория к «Теории LLM»

Небольшой воспроизводимый проект к учебнику. Здесь можно пройти один настоящий шаг обучения маленькой языковой модели и проверить три границы приложения: поиск документа, доступ к базе и повтор webhook.

В каталоге [manual](../manual/README.md) лежат исходный DOCX, код сборки PDF и четыре используемые художественные иллюстрации. Инструкции для повторной сборки книги находятся там же.

## Запуск

Детерминированные команды проверены на Node.js 24.21.0; им не нужны внешние пакеты и сеть. Две команды `live` требуют установленный локальный Ollama и загруженную модель.

```bash
npm test
npm run demo
npm run attention
npm run rag
npm run orders
npm run webhook
npm run evaluate
npm run structured
npm run injection
npm run live
npm run live:evaluate
```

`npm run demo` проходит путь **«я люблю чай» → ID → logits → softmax → loss → градиент → новые logits**. Все числа в [data/training-trace.json](../data/training-trace.json) получены этим же кодом.

`npm run attention` показывает отдельный фиксированный пример **Q·K → causal mask → softmax → сумма V → остаточная связь → logits**. Это одна голова, а не полный трансформер. Числа на странице технического разбора PDF получены из этого примера.

`npm run evaluate` повторяет интервалы Уилсона и метрики поиска из новых атласов. `npm run structured` показывает нормировку после маски допустимых токенов. `npm run injection` симулирует вредоносную инструкцию в найденном документе и проверяет, что read-only runtime отклоняет запись и отправку журнала. Эти программы детерминированные: они не вызывают LLM и не измеряют качество реального провайдера.

`npm run live` и `npm run live:evaluate` обращаются к **локальному Ollama** и действительно запускают языковую модель. Перед ними установите и запустите Ollama, затем выполните `ollama pull qwen2.5:3b`. Первый опыт проводит новый тариф и число заказов через модель и read-only runtime; второй проверяет 12 источниковых случаев. Подробный порядок и критерии разбора — в [живой лаборатории](live-lab.md). Сетевой доступ нужен для первоначальной загрузки модели; сами опыты обращаются только к localhost. Другую локальную модель можно выбрать через `OLLAMA_MODEL`.

## Что именно здесь моделируется

| Опыт | Что работает по-настоящему | Граница вывода |
| --- | --- | --- |
| `src/toy-model.ts` | Биграммная вероятностная модель и точный градиент её cross-entropy loss | Это не трансформер и не обучение LLM; предыдущий токен выбирает строку таблицы параметров |
| `src/tiny-attention.ts` | Расчёт одной головы causal attention на двухмерных векторах | Веса фиксированы; нет позиционных признаков, нормализации, MLP и обучения |
| `src/rag.ts` | Выбор фрагмента, сборка контекста и проверяемый источник цены | Ответ собирает детерминированная функция; LLM не вызывается |
| `src/orders.ts` | Проверка прав перед чтением учебных заказов и трасса результата | Заказы живут в памяти процесса, а не в промышленной БД |
| `src/webhook.ts` | Реальный `UNIQUE`-индекс SQLite и два отдельных процесса, отправляющих один `event_id` | Одна строка в БД не доказывает отсутствие повторных внешних эффектов |
| `src/evaluation.ts` | Точные учебные расчёты интервалов и retrieval-метрик | Интервал требует предпосылок о выборке; три запроса не оценивают качество реального поиска |
| `src/structured-output.ts` | Перенормировка разрешённых продолжений | Это один способ ограничения декодирования, а не поведение любого API |
| `src/security.ts` | Read-only policy отклоняет два вредоносных предложения | Предложения заданы вручную; устойчивость настоящей модели к injection не проверена |

Модель в первом опыте обучает только одну строку logits для контекста «люблю». Один шаг повышает вероятность «чай» с **0,0900** до **0,2953**, но «чай» после шага ещё не самый вероятный вариант. Это важный результат: уменьшение loss не обещает мгновенного правильного ответа.

В PDF тот же шаг показан на вычисленной 3D-поверхности ошибки и на плоской карте. Координаты поверхности — две разности logits относительно цели «чай»; её высота получается из cross-entropy, а не из художественной метафоры.

## Задания

Начните с [docs/exercises.md](exercises.md). Проверочные расчёты и выводы находятся отдельно в [docs/answers.md](answers.md). [docs/math-map.md](math-map.md) кратко связывает символы PDF с переменными кода.
Для графиков и технических схем есть [текстовые описания](visual-descriptions.md) с числами и границами вывода.
Разные режимы обучения и конкретные сигналы разобраны в [карте методов](training-modes.md).
Отдельный [опыт с настоящим токенизатором](tokenization-lab.md) показывает ID и байты `cl100k_base`; для него нужны Python 3 и опциональный пакет `tiktoken`.
Для проверки ясности рукописи на живых читателях есть [протокол пилота](reader-pilot.md); он пока не проведён.
В конце PDF есть одностраничная шпаргалка «Откуда взялся ответ и что проверять». Для собственных проектов подготовлены [пять заполняемых бланков](../templates/README.md): трасса, ТЗ на дообучение, сравнение версий, рубрика свободного ответа и запись сессии с читателем. [Сверка словаря](glossary-audit.md) объясняет, куда ведут все 78 ссылок и почему 25 из них перенесены к более точному разбору. [Решение по четырём иллюстрациям](illustration-audit.md) фиксирует их роль и риски для пилота.

[Интерактивный атлас](../interactive/index.html) открывается как один HTML-файл без установки и сети. Три ползунка показывают softmax при разных температурах, закрытые позиции причинной маски и число параметров LoRA при выбранном ранге. В PDF рядом с основной теорией добавлены метки маршрута чтения; после главы 21 стоят шесть одностраничных дополнений: мультимодальность, ускорение инференса, интерпретируемость, права на данные и веса, агент в продакшене и сравнение версий. Это учебные расчёты и контрольные вопросы, а не измерение качества модели или правовое заключение.

## Как это связано с PDF

- Главы 3, 5 и 7: токены, вероятности, loss и один шаг обновления.
- Главы 12–14: инференс, контекст и RAG.
- Главы 16–17: предложение действия, проверка прав и исполнение.
- Практикум в конце: три задания с тарифом, 42 заказами и повтором webhook.
